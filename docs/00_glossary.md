# 00. 용어집 (Glossary)

설계 문서 전반에서 쓰이는 용어를 분야별로 정리했습니다. 게임 개발이 처음이라면 **[A. 기획](#a-기획--게임-디자인)** 과 **[F. 사업](#f-사업--출시)** 부터 읽으시면 나머지 문서가 훨씬 잘 읽힙니다.

> 각 항목의 `→` 는 그 용어가 실제로 쓰인 문서입니다.

---

## A. 기획 / 게임 디자인

| 용어 | 뜻 |
|---|---|
| **GDD** (Game Design Document) | 게임 기획서. 이 저장소의 `docs/` 전체가 GDD에 해당합니다. |
| **코어 루프** (Core Loop) | 플레이어가 계속 반복하게 되는 행동 사이클. 이 게임은 `비행 → 경로 선택 → 회피/교전 → 상점 → 다시 비행`. → [02](02_core_gameplay.md) |
| **POI** (Point of Interest) | **관심 지점.** 지도에 이름과 아이콘이 찍히는, 플레이어가 일부러 찾아가는 장소. 이 게임에서는 **구름 위 상점 3종**(비행기 스토어·무기점·정비소)을 가리킵니다. 원래 내비게이션 용어예요. → [05](05_map_poi_minimap.md) |
| **USP** (Unique Selling Point) | 이 게임에만 있는 강점. "왜 다른 게임 말고 이걸 사야 하나"에 대한 답. → [01](01_product_overview.md) |
| **온보딩** (Onboarding) | 신규 플레이어가 조작과 규칙을 익히는 초반 경험. 튜토리얼보다 넓은 개념. → [09](09_ui_ux_flow.md) |
| **리텐션** (Retention) | 잔존율. 유저가 떠나지 않고 계속 돌아오는 비율. |
| **D7 리텐션** | 설치 7일 뒤에도 게임을 켜는 유저 비율. `D1`은 다음 날, `D30`은 30일 뒤. 멀티 게임 건강도의 핵심 지표. |
| **세션** (Session) | 게임을 한 번 켜서 끌 때까지, 또는 경기 한 판. |
| **TTK** (Time To Kill) | 적을 격추하는 데 걸리는 시간. 짧으면 실력이 반영될 여지가 없고, 길면 서로를 놓칩니다. 목표 4~7초. → [06](06_combat_items.md) |
| **밸런싱** (Balancing) | 수치를 조정해 특정 전략·기체·아이템만 강해지지 않게 만드는 작업. 출시 후에도 계속됩니다. |
| **역전 보정** / **러버밴딩** (Rubber-banding) | 뒤처진 플레이어에게 유리한 보정을 주는 장치. 마리오카트의 블루셸이 대표적. → [06](06_combat_items.md) |
| **서든데스** (Sudden Death) | 경기가 늘어지지 않도록 강제로 결판을 내는 규칙. 이 게임은 **비행 가능 공역이 좁아지는 방식**. → [04](04_game_modes.md) |
| **스코프 크립** (Scope Creep) | "이것도 넣으면 좋겠는데"가 쌓여 개발 범위가 계속 불어나는 현상. **인디 게임 실패 원인 1위.** → [01 §1.7](01_product_overview.md) |
| **수직 슬라이스** (Vertical Slice) | **아주 짧지만 처음부터 끝까지 실제로 플레이되는 게임 한 조각.** 케이크를 세로로 한 조각 자른 것처럼, 조작·전투·상점·UI가 전부 들어 있되 분량만 최소인 빌드. 재미 여부를 조기에 판단하는 용도. → [13 M1](13_roadmap_milestones.md) |
| **마일스톤** (Milestone) | 개발 일정의 큰 관문. 문서의 `M0`~`M6`이 그것. |
| **게이트** (Gate) | 마일스톤 통과 조건. 못 넘으면 다음 단계로 진행하지 않겠다는 약속. |
| **플레이테스트** | 실제 사람에게 시켜보고 관찰하는 것. 기획자의 예상은 거의 항상 틀립니다. |
| **프로시저럴 생성** (Procedural Generation) | 맵을 사람이 손으로 만들지 않고 규칙과 난수로 자동 생성. 싱글 무한 모드에 사용. → [04](04_game_modes.md) |
| **시드** (Seed) | 난수 생성의 시작값. **같은 시드 = 같은 맵**이라, 주간 리더보드를 공정하게 만드는 장치. |
| **고스트** (Ghost) | 과거 기록 주행을 반투명하게 겹쳐 보여주는 것. 레이싱 게임의 단골 기능. |

## B. 비행 / 조작

| 용어 | 뜻 |
|---|---|
| **스로틀** (Throttle) | 엔진 출력 레버. 자동차의 액셀에 해당. |
| **스로틀 유지** | `Space`를 눌러 기동하는 동안 **직전의 엔진 출력을 그대로 붙잡아 두는 것.** 이게 없으면 상승할 때마다 속도가 떨어집니다. → [03 C-2](03_controls_input_spec.md) |
| **롤 / 피치 / 요** (Roll / Pitch / Yaw) | 비행기의 3가지 회전축. **롤**=좌우로 기울기(`A`/`D`), **피치**=기수 상하(`Space+W/S`), **요**=기수 좌우(`Space+A/D`). |
| **뱅크 턴** (Bank Turn) | 기울인 채로 유지하면 자연스럽게 그 방향으로 선회하는 현상. 실제 비행기의 기본 선회 방식. → [03 C-1](03_controls_input_spec.md) |
| **스톨** (Stall, 실속) | 속도가 너무 느려져 양력을 잃고 기수가 떨어지는 상태. 이 게임은 **조작 불능으로 만들지 않고** 감도만 낮춥니다. → [02 §2.2](02_core_gameplay.md) |
| **부스트** (Boost) | 일시적 최고 속도 증가. `Ctrl`. |
| **모디파이어** (Modifier) | 다른 키의 의미를 바꾸는 보조 키. `Shift+클릭`의 `Shift` 같은 것. 이 게임은 `Space`가 모디파이어. → [03](03_controls_input_spec.md) |
| **오토파일럿** (Autopilot) | 자동 비행. 상점 UI를 여는 동안 기체가 알아서 선회하게 하는 처리. |
| **Auto-level** | 기체를 자동으로 수평으로 되돌리는 보조. 지도를 여는 동안 추락 방지용. |
| **FOV** (Field of View) | 시야각. 넓히면 더 많이 보이고 **속도감이 커집니다.** 멀미와도 직결. |
| **모션 시크니스** (Motion Sickness) | 화면 흔들림으로 인한 멀미. 비행 게임의 고질적 환불 사유라 옵션으로 반드시 끌 수 있어야 합니다. → [11](11_art_audio_direction.md) |
| **데드존 / 입력 램프** | 아날로그 스틱의 무반응 구간 / 키보드 입력을 부드럽게 만드는 가속 곡선. |

## C. 전투

| 용어 | 뜻 |
|---|---|
| **히트박스** (Hitbox) | 맞았는지 판정하는 눈에 안 보이는 충돌 영역. 보이는 모델과 다를 수 있습니다. |
| **히트스캔** (Hitscan) | 총알이 날아가는 시간 없이 **즉시 맞는** 방식. 반대는 **투사체(Projectile)**. |
| **탄속 / 리드샷** | 총알 속도 / 움직이는 적의 **앞을 조준**해서 쏘는 것. 탄속이 유한하면 리드샷이 필요합니다. |
| **락온** (Lock-on) | 유도 무기가 대상을 조준·추적하는 상태. `RMB` 홀드. |
| **쿨다운** (Cooldown) | 재사용 대기 시간. |
| **DPS** (Damage Per Second) | 초당 피해량. 무기 강함의 비교 단위. |
| **어시스트** (Assist) | 직접 격추하진 않았지만 피해를 기여한 것에 대한 보상. |
| **킬 피드** (Kill Feed) | 화면 구석에 "누가 누구를 잡았다"가 흘러가는 목록. |
| **FF** (Friendly Fire) | 아군 오사. 이 게임은 **없음**. |
| **FFA** (Free For All) | 팀 없는 전원 각자도생. 개인전 배틀. |
| **라스트맨스탠딩** | 최후 1인 생존이 승리. |

## D. 네트워크 / 멀티플레이

여기가 가장 낯선 영역일 텐데, **"화면에 보이는 것과 서버가 아는 것이 다를 수 있다"** 는 문제를 푸는 용어들입니다.

| 용어 | 뜻 |
|---|---|
| **서버 권위** (Server-authoritative) | **서버가 결정한 것만 진짜**로 취급하는 구조. 클라이언트 말을 믿으면 핵이 만연합니다. → [08](08_multiplayer_architecture.md) |
| **클라이언트** (Client) | 각 플레이어의 게임 프로그램. |
| **P2P** (Peer to Peer) | 서버 없이 플레이어끼리 직접 연결. 공짜지만 치팅에 취약. |
| **전용 서버** (Dedicated Server) | 게임만 돌리는 별도 서버. 공정하지만 **월 비용이 계속** 나갑니다. |
| **리슨 서버** (Listen Server) | **플레이어 한 명(방장)의 PC가 동시에 서버 역할**을 하는 방식. 비용 0. 이 게임의 v1.0 선택. |
| **호스트** (Host) | 리슨 서버를 돌리는 그 플레이어. = 방장. |
| **호스트 마이그레이션** | 호스트가 나갔을 때 다른 사람에게 서버 역할을 넘기는 것. v1.0에서는 미지원. |
| **틱레이트** (Tick Rate) | 서버가 초당 몇 번 게임 상태를 계산하는지. 30Hz = 초당 30번. |
| **핑 / RTT** (Round Trip Time) | 내 PC ↔ 서버 왕복 지연 시간(ms). 낮을수록 좋음. |
| **레이턴시 / 랙** | 지연 / 지연 때문에 생기는 버벅임. |
| **리플리케이션** (Replication) | 서버의 게임 상태를 각 클라이언트로 복제·동기화하는 것. |
| **클라이언트 예측** (Prediction) | 서버 응답을 기다리지 않고 **일단 내 화면에서 먼저 움직이는 것.** 안 하면 키 누르고 0.1초 뒤에 반응해서 못 씁니다. |
| **화해 / 롤백** (Reconciliation / Rollback) | 예측이 서버와 어긋났을 때 **과거로 되감아 다시 계산**해 바로잡는 것. |
| **보간** (Interpolation) | 띄엄띄엄 오는 위치 정보 사이를 부드럽게 채워 그리는 것. |
| **외삽** (Extrapolation) | 정보가 안 올 때 **이전 속도로 계속 갈 것이라 추측**해 그리는 것. |
| **랙 보상** (Lag Compensation) | 핑이 높은 사람의 조준을 **과거 시점으로 되감아 판정**해 주는 것. "분명 맞췄는데 안 맞음"을 줄입니다. |
| **관련성 / 컬링** (Relevancy / Culling) | 멀리 있어 안 보이는 대상은 정보를 덜 보내 대역폭을 아끼는 것. |
| **로비** (Lobby) | 경기 전 대기 공간. 이 게임의 **방**. |
| **매치메이킹** (Matchmaking) | 조건에 맞는 방·상대를 자동으로 찾아주는 것. |
| **레디** (Ready) | 준비 완료 상태. 전원 레디 시 방 설정이 **잠깁니다**. → [04 §4.6](04_game_modes.md) |
| **SDR** (Steam Datagram Relay) | Valve가 무료 제공하는 릴레이 망. **IP 노출 방지 + DDoS 방어 + 접속 안정화**를 한 번에 해결. |
| **경합 / 레이스 컨디션** (Race Condition) | 두 일이 거의 동시에 일어나 순서가 꼬이는 버그. "마지막 사람이 레디 누르는 순간 방장이 맵 변경" 같은 상황. |
| **봇** (Bot) | 사람 대신 채우는 AI 플레이어. 동접이 적을 때의 생존 장치. |

## E. 기술 / 엔진 / 아트

| 용어 | 뜻 |
|---|---|
| **엔진** (Game Engine) | 게임 제작 기반 소프트웨어. Unreal, Unity 등. |
| **Unreal Engine** | Epic Games의 엔진. 이 프로젝트의 권장 선택. → [10](10_tech_stack.md) |
| **블루프린트** (Blueprint) | Unreal의 **비주얼 스크립팅**. 코드 대신 노드를 선으로 연결해 로직을 짭니다. |
| **Lumen / Nanite** | Unreal 5의 실시간 광원 / 초고밀도 지오메트리 기술. 예쁘지만 무겁습니다. 이 프로젝트는 **Lumen 미사용**. |
| **볼류메트릭 클라우드** | 진짜 부피가 있는 구름. 통과해서 지나갈 수 있습니다. 이 게임의 핵심 비주얼. |
| **LOD** (Level of Detail) | 멀리 있는 물체를 단순한 모델로 바꿔 성능을 아끼는 기법. |
| **드로우콜** (Draw Call) | GPU에 "이거 그려"라고 명령하는 횟수. 많으면 느려집니다. |
| **폴리곤 / 트라이앵글(tris)** | 3D 모델을 이루는 삼각형 면. 많을수록 정교하고 무겁습니다. |
| **머티리얼 / 셰이더** | 표면의 재질·색·반사 표현 / 그걸 계산하는 프로그램. |
| **VFX** (Visual Effects) | 폭발, 연기, 속도선 같은 이펙트. Unreal에서는 **Niagara**로 제작. |
| **UMG** | Unreal의 UI 제작 도구. |
| **프레임 / fps** | 초당 화면 갱신 횟수. 이 게임은 **60fps가 타협 불가 요구사항**. |
| **프레임 타임** | 한 프레임 그리는 데 걸린 시간. 60fps = 16.6ms. |
| **히칭** (Hitching) | 순간적으로 화면이 멎는 끊김. 주로 로딩·스트리밍이 원인. |
| **스트리밍** (Level Streaming) | 넓은 맵을 통째로 안 올리고 **가까운 구역만 그때그때 불러오는 것**. |
| **데이터 테이블 / 데이터 주도 설계** | 수치를 코드가 아닌 **CSV 표에 두는 것.** 프로그래머 없이 밸런스 수정이 가능해집니다. → [10 §10.5](10_tech_stack.md) |
| **하드코딩** | 수치를 코드에 직접 박아 넣는 것. 수정할 때마다 재빌드가 필요해 밸런싱의 적. |
| **빌드 / 패키징** | 개발 중인 프로젝트를 실행 가능한 게임으로 굽는 것. |
| **CI** (Continuous Integration) | 코드를 올릴 때마다 자동으로 빌드·검사하는 체계. |
| **Git / LFS** | 버전 관리 도구 / 대용량 바이너리(3D 모델, 사운드)를 다루는 확장. |
| **QA** (Quality Assurance) | 품질 검증. 버그 찾는 일. |
| **LQA** (Localization QA) | 번역 검수. 글자 잘림, 오역, 문맥 오류를 잡습니다. |
| **현지화 / i18n / L10n** | 다국어 대응. 문자열을 코드에서 분리하는 것이 전제. |
| **텔레메트리** (Telemetry) | 익명 플레이 통계 자동 수집. **밸런싱의 유일한 객관적 근거.** |
| **옵트아웃** (Opt-out) | 기본은 켜져 있되 유저가 끌 수 있게 하는 것. 통계 수집에 필수. |
| **핫픽스** (Hotfix) | 심각한 문제를 급히 고쳐 내보내는 긴급 패치. |

## F. 사업 / 출시

| 용어 | 뜻 |
|---|---|
| **Steamworks** | Valve의 개발자용 관리 도구. 스토어 페이지, 빌드 업로드, 매출 확인 전부 여기서. |
| **Steam Direct** | Steam 출시 등록 절차. **앱당 $100** (누적 매출 $1,000 달성 시 환급). |
| **앱 ID / 뎁포(Depot)** | 게임 고유 번호 / 게임 파일이 담기는 저장 단위. |
| **SteamPipe** | Steam에 게임 파일을 업로드하는 시스템. |
| **위시리스트** (Wishlist) | 유저가 찜해두는 것. **출시 첫 주 판매량과 가장 강하게 연동되는 단일 지표.** |
| **전환율** (Conversion Rate) | 위시리스트가 실제 구매로 이어지는 비율. 첫 주 8~20% 수준. |
| **Next Fest** | Valve의 미출시 게임 데모 축제. **인디에게 가장 강력한 무료 마케팅.** 게임당 1회만 참가 가능. |
| **얼리 액세스** (Early Access, EA) | **미완성 상태로 먼저 유료 판매**하는 방식. 매출을 앞당기고 실사용자 밸런스 데이터를 얻습니다. |
| **BEP** (Break-even Point) | 손익분기점. 여기까지 팔아야 본전. 이 프로젝트는 **약 12,000장**. |
| **실수령률** | 정가 중 실제로 통장에 들어오는 비율. Steam 수수료·할인·환불·세금을 뺀 뒤 **약 45%**. |
| **레비뉴 셰어** (Revenue Share) | 매출 분배. Steam은 **30%**를 가져갑니다. |
| **로열티** (Royalty) | 엔진 사용료. Unreal은 매출 100만 달러 초과분의 5%. |
| **F2P** (Free to Play) | 무료 배포 후 아이템 판매로 수익. 상시 운영 인력이 필요해 이 프로젝트는 **미채택**. |
| **P2W** (Pay to Win) | 돈 쓰면 강해지는 구조. **멀티 게임 리뷰를 파괴합니다.** |
| **코스메틱** (Cosmetic) | 성능에 영향 없는 외형 상품(도색, 스킨). P2W를 피하는 유일한 안전한 유료 상품. |
| **DLC** (Downloadable Content) | 추가 콘텐츠 상품. |
| **그라인딩** (Grinding) | 같은 걸 반복해야 하는 지루한 성장 구조. |
| **동접** (CCU, Concurrent Users) | 동시 접속자 수. **멀티 게임의 생존 지표.** |
| **리뷰 긍정률** | Steam 리뷰 중 긍정 비율. 80% 이상이 "긍정적" 배지의 기준선. |
| **키(Key) 배포** | 스트리머·언론에 무료 코드를 주는 것. Steam이 무료로 발급해 줍니다. |
| **환불 정책** | Steam은 **구매 2주 이내 & 플레이 2시간 미만**이면 대체로 환불해 줍니다. |
| **GRAC / ESRB / PEGI** | 한국·북미·유럽의 게임물 등급 분류 기관. |
