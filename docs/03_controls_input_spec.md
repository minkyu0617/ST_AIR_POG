# 03. 조작 & 입력 스펙

## 3.1 확정 키 매핑 (기본값)

| 입력 | 동작 | 분류 |
|---|---|---|
| `W` | 속도 가속 | 추력 |
| `S` | 속도 감속 (후진 없음, 최소 속도에서 하한 클램프) | 추력 |
| `A` | 기체 좌 기울기 (롤 −) | 자세 |
| `D` | 기체 우 기울기 (롤 +) | 자세 |
| `Space` (홀드) | **벡터 기동 모드 진입** (모디파이어) | 모디파이어 |
| `Space + W` | 기수 상승 / 위로 이동 | 벡터 기동 |
| `Space + S` | 기수 하강 / 아래로 이동 | 벡터 기동 |
| `Space + A` | 좌로 방향 이동 (요 좌선회) | 벡터 기동 |
| `Space + D` | 우로 방향 이동 (요 우선회) | 벡터 기동 |
| `Ctrl` | 부스트 (3초, 쿨다운 8초) | 추력 |
| `Alt` | 아이템 슬롯 순환 변경 | 장비 |
| `Tab` (홀드) | 전체 지도 열기 | 정보 |
| `LMB` | 선택 중인 무기/아이템 사용 | 전투 |
| `RMB` (지도 상태) | 커서 지점 팀 공유 핑 (닉네임 마크) | 커뮤니케이션 |

## 3.2 입력 충돌 및 해소 — **개발 전 반드시 확정할 것**

원안을 그대로 구현하면 아래 6개 문제가 발생합니다. 각각에 대해 **권장안**을 제시하니 검토 후 확정해 주세요. (미결정 항목 요약: [14번 문서](14_open_questions.md))

---

### C-1. `A`/`D`의 비대칭 정의 ⚠️

원안 표기:
- `A : 기체가 왼쪽으로 기울어짐`
- `D : 기체가 오른쪽으로 기울어짐 **오른쪽으로 방향 이동**`

D에만 "방향 이동"이 붙어 있어 좌우 동작이 비대칭입니다. 오타로 판단됩니다.

**권장안**: `A`/`D`는 **대칭적으로 롤(기울기)만** 담당. 단, 실제 비행기처럼 **롤 유지 시 완만한 선회가 자연 발생**하게 합니다(뱅크 턴).
- 롤 30° 유지 → 약 12°/s 선회
- 롤 75° 유지 → 약 34°/s 선회
- 이렇게 하면 "A/D도 결국 방향이 바뀐다"는 원안의 의도가 물리적으로 자연스럽게 충족되고, `Space+A/D`는 **롤 없이 즉각적으로 기수를 꺾는 급기동**으로 역할이 명확히 분리됩니다.

| | A/D 단독 | Space + A/D |
|---|---|---|
| 성격 | 완만·우아·속도 손실 적음 | 급격·즉각·속도 손실 큼 |
| 속도 손실 | −3%/s | −12%/s |
| 용도 | 코스 주행, 미세 조정 | 회피 기동, 조준 |

### C-2. `Space` 홀드 중 `W`는 가속인가 상승인가? ⚠️

`W`는 가속, `Space+W`는 상승. **Space를 누른 채로는 가속을 못 하게 됩니다.** 레이스 중 "상승하면서 가속"은 매우 빈번한 요구입니다.

**권장안 (택1 — A안 권장)**

- **A안 (권장) · 자동 스로틀**: `Space` 홀드 중에는 **직전 스로틀 값이 유지**됩니다. 즉 W로 최대 가속 상태에서 Space를 누르면 최대 추력을 유지한 채 상승합니다. 별도 키가 필요 없고, "속도를 유지한 채 기동한다"는 아케이드 감각에 맞습니다.
- B안 · `Shift`를 가속에 추가 할당하여 Space 홀드 중 `Shift`로 가속. → 키 개수 증가, 캐주얼 타깃에 불리.
- C안 · Space를 홀드가 아닌 **토글**로. → 상태 인지 실수 유발, 비권장.

---

### C-3. `Alt` + `Tab` = 창 최소화 사고 🔴 **심각**

`Alt`(아이템 변경)와 `Tab`(지도)이 모두 핵심 키입니다. 전투 중 **거의 확실하게 `Alt+Tab`이 동시 입력되어 게임이 최소화**됩니다. 이건 리뷰에서 반드시 지적당하는 종류의 버그입니다.

**권장안 (전부 적용)**
1. **기본 키 변경**: 아이템 변경을 `Alt` → **`Q`** 로 이동. (`Alt`는 대안 바인딩으로 유지)
   - 근거: `Q`는 좌수 검지가 `WASD` 홈 포지션에서 손을 떼지 않고 누를 수 있는 유일한 키이며, 대부분의 슈터에서 "무기 전환"의 관례 위치입니다. `Alt`는 새끼손가락 사용 + OS 예약 키라는 이중 결함이 있습니다.
2. **마우스 휠**로도 아이템 순환 지원 (관례적이며 학습 불필요).
3. `1` `2` `3` 숫자키로 슬롯 직접 선택 (숙련자용).
4. 창 모드는 **Borderless Fullscreen 기본** + 게임 내 `Alt+Tab` 가로채기 옵션 제공.
5. 지도는 `Tab` **홀드** 방식이므로 `Alt+Tab` 조합이 성립할 여지 자체를 줄임 — 지도가 열린 동안 `Alt` 입력은 아이템 변경으로 소비하고 OS 전달을 차단.

> **원안 유지를 원하시면** `Alt`를 그대로 두되 최소 4·5번은 필수입니다. 그래도 사고를 100% 막지는 못합니다.

---

### C-4. `Tab` 지도: 홀드 vs 토글, 그리고 "그동안 비행기는?"

배틀그라운드는 지상 게임이라 지도를 여는 동안 서 있어도 됩니다. **비행기는 멈출 수 없습니다.**

**권장안**
- **홀드 방식**(누르는 동안만) 기본. 토글은 옵션.
- 지도가 열려 있는 동안 **게임은 멈추지 않으며**, 화면 중앙 30% 영역에 **반투명으로 전방 시야를 유지**합니다 (지도는 좌우/상단에 배치, 중앙 개방).
- **자동 수평 유지(Auto-level) 보조**가 지도 오픈 중에만 활성화되어 급추락을 방지합니다. 조작 입력은 여전히 받습니다.
- 지도 오픈 중 마우스 커서가 나타나며 `RMB` 핑이 가능합니다. 이때 `LMB`(아이템 사용)는 **비활성화**하여 오발을 방지합니다.
- **최대 연속 오픈 시간 제한 없음**, 단 전투 모드에서 지도를 여는 동안 피격 시 자동으로 닫힙니다.

---

### C-5. `RMB`가 비행 중에는 놀고 있음

원안에서 `RMB`는 지도에서만 사용됩니다. 비행 중 우클릭이 비어 있는 것은 낭비이며, 유저는 반사적으로 누릅니다.

**권장안**: 비행 중 `RMB` = **조준 보조 / 락온 유지**.
- 홀드 시 시야각 20° 내 최근접 적을 락온, 카메라가 살짝 줌인되며 유도 무기 발사 조건이 됩니다.
- 락온 없이도 무유도 무기는 발사 가능하므로 필수 조작은 아님 → 캐주얼 타깃 부담 없음.

---

### C-6. 싱글플레이의 "적 전투기를 물리친다"에 쓸 무기가 정의되지 않음

원안에서 `LMB`는 "아이템 사용"이고, 아이템은 전투 모드에서 주어집니다. **싱글플레이에서 적기를 격추할 수단이 명시되지 않았습니다.**

**권장안**: **슬롯 0에 무한 탄약 기본 기총(Vulcan)을 상시 장착**합니다.
- 데미지 8/발, 연사 12발/초, 과열 게이지(2.5초 연사 후 3초 쿨다운)
- 아이템 슬롯이 비어 있으면 자동으로 기총이 선택됨 → `LMB`는 **항상 무언가를 발사**하며 "눌렀는데 아무 일도 없음"이 발생하지 않음
- 이 결정으로 싱글/스피드/전투 **전 모드에서 `LMB`의 의미가 통일**됩니다.

## 3.3 입력 상태 머신

```
                 ┌──────────────┐
        ┌───────►│   FLIGHT     │◄────────┐
        │        │ (기본 비행)   │         │
        │        └──┬────────┬──┘         │
        │           │        │            │
   Tab 해제    Space 홀드   Tab 홀드    Space 해제
        │           │        │            │
        │           ▼        ▼            │
        │      ┌─────────┐ ┌──────────┐  │
        │      │ VECTOR  │ │ MAP_OPEN │  │
        │      │ 벡터기동 │ │ 전체지도  │  │
        │      └─────────┘ └────┬─────┘  │
        └───────────────────────┘        │
                                          │
                    ┌────────────────┐    │
                    │  STALL / DOWN  │────┘
                    │  (입력 감쇠)    │
                    └────────────────┘
```

**우선순위 규칙**
1. `MAP_OPEN` 중에도 `FLIGHT`/`VECTOR` 조작은 계속 처리됩니다 (비행기는 멈추지 않으므로).
2. `MAP_OPEN` 중 `LMB` 무기 발사는 차단, `RMB`는 핑으로 재해석됩니다.
3. `Ctrl` 부스트는 모든 상태에서 발동 가능하되, `STALL` 중에는 무시됩니다.
4. `STALL` 중 조작 입력 감도 40%. 완전 차단하지 않습니다.

## 3.4 게임패드 매핑 (Steam Deck 대응 필수)

| 게임패드 | 동작 |
|---|---|
| `RT` | 가속 (W) |
| `LT` | 감속 (S) |
| `왼쪽 스틱 좌/우` | 롤 (A/D) |
| `왼쪽 스틱 상/하` | 피치 (Space+W/S 상당) |
| `오른쪽 스틱` | 카메라 프리룩 |
| `LB` | 벡터 기동 모디파이어 (Space) |
| `RB` | 무기/아이템 사용 (LMB) |
| `A` | 부스트 (Ctrl) |
| `Y` | 아이템 변경 (Q) |
| `View/Select` (홀드) | 전체 지도 |
| 지도 중 `RB` | 핑 |

- 게임패드는 아날로그 입력이므로 **키보드보다 미세 조작에 유리**합니다. 밸런스 왜곡을 막기 위해 키보드 입력에는 **0.12초 가속 램프**를 적용해 디지털 입력의 급격함을 완화합니다.
- Steam Input API로 커뮤니티 레이아웃 지원.

## 3.5 접근성 & 리바인딩

- **전체 키 리바인딩 필수** (Steam 리뷰 감점 요인 1순위).
- 지도 홀드/토글 전환 옵션, 부스트 홀드/토글 전환 옵션.
- 색약 모드 3종 (적록/청황/전색맹) — 팀 구분 색과 피아 식별에 직결되므로 필수.
- 모션 시크니스 대응: 카메라 흔들림 강도 0~100% 슬라이더, 시야각(FOV) 70~110 조절, 속도선 이펙트 ON/OFF.
- 자막/토스트 크기 3단계.
